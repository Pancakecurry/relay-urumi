# Store Orchestration — M5 visual direction and review

Use the M4 graphite surfaces, Geist/GeistMono, restrained teal, semantic states and project-owned controls. A searchable store rail leads into a persistent workspace instead of a modal hiding a long phase dump. Store identity, lifecycle state, created time, host and authorized actions remain visible. The shared gateway is contextual navigation, not a fabricated infrastructure counter.

Infrastructure nodes come from the private provisioner's tenant-bound Kubernetes observation. Relationships are returned by that observer, with namespace/workload/PVC identities checked against desired state. Selecting a node reveals actual image, readiness, resource requests/limits, sampled usage and safe diagnostics. The desktop inspector sits alongside the map; smaller screens focus the details and provide a return-to-map control. Allocated capacity is explicitly separate from disk usage. Missing metrics remain Unavailable. Current pod state, sampled discovery and durable lifecycle status are distinct signals.

Lifecycle steps map to real controller checkpoints: request/operation, verified namespace, resource setup, successful Helm/store readiness, database and bootstrap checks, discovery/registration and Ready. Elapsed time derives from actual operation/event timestamps. Generations and retries remain visible; a superseded attempt is not silently relabelled successful. Historical completion can imply an earlier verified gate, but the UI says when its individual timestamp was not recorded. No progress percentages are synthesized.

Deletion confirms the exact name and explains irreversible data loss. The workspace switches to route denial, drain, uninstall, namespace removal, volume removal, credential cleanup and final verification. Deleted is rendered only after the durable controller gate; inability to observe a terminating namespace is shown as unknown, not absent. Failed and RecoveryRequired states explain the failure location and whether retry, credential restoration, ownership review or cleanup inspection is safe.

Tools use the logged-in gateway discovery/policy engine. Expanding a tool shows its actual input/output schema and immutable store alias. Search, switching, navigation, copy, retry/repair, creation and deletion are real actions. Tabs support keyboard navigation, dialog focus is managed by the existing Radix primitive, reduced motion is respected, and responsive overflow is tested.

Initial current-run captures `visual/01-before-overview.png` and `02-before-detail.png` established the baseline. Review found a long event-list modal, absent live component inspection and details below a tall map. The orchestration layout addresses these in the existing design system. First new visual harness failure was an unscoped schema-heading locator, not a false success; it was corrected to the actually expanded tool. Final screenshot/interaction results are in `visual/review.json`; failure/retry/deletion/create screenshots accompany the real acceptance flows.

Review scope is the assessment's local developer product, not a claim of full WCAG certification. Text contrast, focus, tab access, dialogs, responsive reflow and real data source checks are recorded separately. Screen-reader certification and broader accessibility/performance expansion remain C10, and this lifecycle inspector is not a substitute for the full C1 Flight Recorder.


Final numbered review: (1) overview uses real status counts and searchable identities; (2) topology aligns selectable actual components with the desktop inspector and focused mobile details; (3) lifecycle distinguishes operation generation, elapsed time, fault/retry and verified cleanup; (4) schemas preserve readable code and internal scrolling; (5) failure UI explains missing Secret/ownership/timeout recovery with real retry; (6) deletion requires the exact name and shows verification only after resource absence. Final screenshots03–09 were inspected for density, spacing, long-ID wrapping and controls at desktop/mobile. Ten sampled contrast states have minimum6.79 with no failures. The completed-delete rail now reads Resources removed. No remaining blocking visual defect was found within the tested viewports; broader assistive-technology certification remains later scope.
