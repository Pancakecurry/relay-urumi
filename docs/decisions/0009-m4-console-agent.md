# ADR 0009 — Relay control room and bounded chat

Status: accepted and tested locally at M4 Gate A. M3 known-good release remains `m3-verified`; M4 is a separately verified checkpoint.

React 19.3, Vite 8.3, TanStack Query 5, React Router 7 and Radix Dialog provide the owned SPA. There was no prior frontend/design system to preserve. Navigation and focus behavior use real links, native controls and a trapped, labelled dialog. Geist sans/mono are self-hosted under SIL OFL; Lucide icons are ISC. No external asset traffic or paid UI service.

The visual hierarchy uses graphite surfaces, compact technical typography and one restrained teal accent. The connection map is the actual registry/discovery relationship, with sampled state and checked time. No fabricated load, latency or topology. Source principles: [Linear](https://linear.app/now/behind-the-latest-design-refresh) for calm hierarchy, [Railway](https://docs.railway.com/overview/the-basics) for service relationships, [LangSmith](https://docs.langchain.com/langsmith/observability-quickstart) for nested operation inspection, [Geist](https://vercel.com/geist/introduction) for consistency. These are references, not copied assets. M4's execution inspector does not implement C1 Flight Recorder.

Server state lives in Query; navigation/form/dialog state is local. Browser cookies are HttpOnly; the client selects a team but cannot select its actor. Every chat MCP request obtains a fresh server-derived delegation validated by the gateway. Tools are discovered and executed only through its official MCP client. Upstream credentials and provider key never reach the browser. Durable runs/events are tenant scoped and owner filtered; gateway audit IDs in results connect the two records.

Use AI SDK 7.0.135 with Google adapter 4.0.93 directly against Gemini Developer API. The initial gemini-2.5-flash-lite attempt failed before tool execution. Google's current model page restricts 2.5 to prior users; this key already succeeded with gemini-3.5-flash-lite in M0. Select that verified stable model, without silently falling back to a more expensive provider.

[Model documentation](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite) and [pricing](https://ai.google.dev/gemini-api/docs/pricing), rechecked October 11, list $0.30/M input and $2.50/M output including thinking. The provider request validator enforces the exact model/generateContent path, 32,768 serialized input bytes, 1,536 maximum output tokens, one candidate, minimal thinking without returned thoughts, and function declarations only. [Google thinking documentation](https://ai.google.dev/gemini-api/docs/thinking) confirms max_output_tokens is an infrastructure-enforced combined thought/output cutoff. Google bounds total generated tokens with maxOutputTokens; no search, grounding, caching, image generation or paid auxiliary tools. No retries; 45-second provider timeout. At conservative ₹200/USD plus 50% margin, (32,768 * 0.30 + 1,536 * 2.50) / 1,000,000 * 300 = ₹4.10; ₹5 is the final irreversible reservation for future requests. This calculation relies on the enforced output cap, rather than the model's full 65,536-token capacity. Unit checks reject larger/auxiliary requests before network traffic.


Four model steps, eight serial tools, bounded schema count/result bytes, 180-second run ceiling, explicit unknown outcomes and no ambiguous write retries. Tool results/descriptions are untrusted. Cancellation or restart requires audit/store inspection before retrying mutations. Runs persist across restarts; stale running records are marked unknown before the next run. Cross-replica cancellation and automatic recovery are not claimed at M4; M8 covers replica behavior.

API-only model egress permits public IPv4 HTTPS excluding private/metadata ranges. Standard Kubernetes NetworkPolicy does not bind a domain; the provider adapter additionally fixes HTTPS hostname and rejects redirects. No model key mount/egress on gateway, utilities or static dashboard. This residual broader IP egress is documented rather than described as an FQDN firewall.


The midnight acceptance caught a model semantic error: October 10 UTC was incorrectly reused as the local date after midnight October 11 IST. That answer is retained as failed semantic evidence, even though transport/tools succeeded. The agent now states the current Asia/Kolkata date explicitly and instructs Calendar to compute today by omitting date. The acceptance requires the new order within the real list_orders page, not a compensating get_order.
