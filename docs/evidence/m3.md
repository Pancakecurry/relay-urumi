### Failure, enforcement and persistence

- Captured diagnostic upstream headers prove static server credentials are supplied, caller personal keys/cookies/user headers are absent, and no-auth registration supplies no auth header. Credential edits are write-only; forbidden header names and destinations fail. Secrets never enter Helm values/history or public/audit payloads.
- A real paused tool with a 500ms configured deadline returned `UPSTREAM_TIMEOUT` in **532ms**. Explicit cancellation reaches the upstream and records `CALL_CANCELLED`.
- Five concurrent real delayed calls yield four successes and one `CONCURRENCY_LIMIT`; the denied request completes in 99ms. Shared key admission permits initialize plus 119 lists, then rejects the next request at the 120/minute bound.
- Scaling actual Calendar to zero reports Unreachable without breaking cached discovery, healthy Totals or readiness. Healthy call took **59ms**. The artifact's `catalogDurationMs: 288` includes catalog plus subsequent healthy-call/readiness measurements; it is not a pure catalog benchmark. Calendar was restored.
- Runtime database roles are neither superusers nor BYPASSRLS. A team transaction sees its scope; a rolled-back/reused connection has no tenant context and sees no team rows. Runtime application role cannot read identity password/session-token tables.
- Removing audit INSERT privilege rejects a real product write before side effects; the synthetic test SKU count remains **0**. Privilege was restored. Replacing the owned PostgreSQL pod preserves **34/34** captured audit rows, registry and usable identities/keys, with the same PVC UID.
- Trusted internal delegation derives B from a real session despite a forged A user ID in the request body. Gateway attributes the call to B. Signing out B invalidates the next delegated call. His separate personal key remains independent.
- Valid browser Origin passes. Foreign Origin, oversized body, malformed protocol and forged cookie fail. Boundary rejections are durably attributed to B when a valid key is available. Unknown random keys generate anonymous security events; no user attribution is fabricated.
- Default-deny policies reject unlabelled pods and gateway-labelled pods in the wrong namespace. The gateway reaches only approved data/API/upstreams; direct WordPress/MariaDB access fails. API service-account permissions permit GET/UPDATE only the fixed gateway credential Secret, with list/create/other Secrets denied. Gateway has no mounted Kubernetes API token. No public PostgreSQL/Redis route exists.

The 18 main tool results match durable audit IDs including successes, upstream business failures and rejected calls. Records carry actor, key/delegation kind, server/original tool/alias, UTC timestamps, duration, outcome and argument hash, without raw customer arguments/results or credentials. Member audit views return only self; admin views remain team-scoped. Cancelled requests share one finalization promise. Interrupted audit starts are reconciled to unknown after 30 seconds on the next team gateway request, with no automatic write replay.

## Failed or blocked

No final local M3 runtime gate is failing. The following execution problems were repaired and retested:

- Initial PostgreSQL startup connection refusal and reserved index name: migration now waits for database readiness, uses the corrected identifier and a dedicated advisory-lock connection; application readiness requires migration presence.
- A manually constructed rejected result lacked modern SDK `resultType`: rejection handling now runs through the official SDK. Actual modern/legacy tests pass.
- Disconnect completion competed with callback finalization: one finalization promise and propagated raw-response cancellation fix audit outcome attribution.
- SDK Origin allowlists expect hostnames rather than full URLs: use the documented hostname format plus an additional exact scheme/host/port Origin check. Positive and negative browser tests pass.
- The SDK default advertised change notifications without a tested subscription path. Explicitly set `tools.listChanged: false` using the pinned SDK options; the entire live suite and Inspector advertisement check passed again.
- A role-inspection test queried a schema the application role is intentionally forbidden to access: inspect ACLs as operator and directly prove the expected runtime denial; no permission was broadened.
- Web-view and Python default CA retrieval failed for the brief. OS curl fetched the public export with ordinary TLS validation, and its content matched. No TLS verification bypass was used.

Residual limits remain explicit: local HTTP is unencrypted; no public TLS/VPS/SMTP/email-verification acceptance exists. Hostile-container isolation, OAuth consent/discovery, full Secret rotation/reconciliation, generated store namespaces and alternate Service CIDRs belong to their planned milestones. The current reviewed destination set is conservative; external IPv6 is rejected. Cache polling is lazy per active team, with explicit client refresh/reconnect. The gateway explicitly advertises `tools.listChanged: false`; this stateless deployment uses tested refresh/reconnect. This is not an HA/load-capacity claim.

SQL and Kubernetes Secret writes are not a distributed transaction; a crash can leave an unused credential slot requiring operator cleanup. Total database outage cannot durably record the rejection that the outage causes; dispatch fails closed. Final audit failure after a completed upstream mutation can produce an unknown outcome requiring operator reconciliation, never an automatic mutation retry. These limits are documented rather than hidden.

## Architecture decisions

Keep the accepted TypeScript/Fastify/official SDK v2/Better Auth/Drizzle baseline. Introduce only M3 services: PostgreSQL identity/registry/audit and Redis shared admission limits. No queue or model service was installed. Separate API/gateway authorization surfaces and migration/auth/application database roles; derive all actors server-side. Team policies govern upstream read/write capability even though the private Woo credential is read/write. Stable 45-character aliases derive from immutable registration UUID plus original name; display names do not determine routing.

The fixed Secret manager is a narrowly privileged module in the API, not an unnecessary additional process. A signed 60-second platform-internal credential is trusted session delegation, not a substitute for planned external OAuth. Core runtime source fingerprint includes SQL migrations as well as application/config/lock inputs. Exact package/image versions and permission/network constraints are pinned and recorded.
