## Failed or blocked

Repaired: generated Dockerfile newline parse failure; Python's local certificate trust failure (used system curl with normal TLS verification); Node fetch Host mismatch (used node:http); outdated confirmation selector (real order succeeded, corrected assertion); missing Node globals in lint configuration.

**Credential-prompt defect:** WP-CLI `--prompt=admin_password` echoed the initial administrator password. Replaced with PHP reading its Secret file, rotated the affected password, deleted the old test hook and replaced the raw capture before staging. Empty-store installation and final log/evidence/index scans verify the corrected path. The rejected prompt is not used by current source. No credential is committed; no password value is repeated in this report.

Disclosed limits: upstream entrypoints/root bootstrap are incompatible with an untested forced non-root/restricted policy. Apache workers actually run as www-data, MariaDB as mysql; writable roots and root initialization remain. WP-CLI emits an Apache hard-rewrite warning; actual pinned `.htaccess`/pretty REST/product/cart/checkout routes pass. SMTP is absent and admin order notes accurately report failed email notifications; mail delivery is not implemented. Single-node local-path is not backup/restore or HA. Public TLS/VPS, amd64 execution and registry publication remain unverified/unprovisioned. None blocks the locally verified M1 store.

## Architecture decisions

[ADR 0006](../decisions/0006-persistent-store.md): dedicated namespace/database/content; immutable input image/plugin pins; offline bootstrap; pre-generated stable REST credential plus WooCommerce hash lookup for retry; dedicated service role; single-writer/Recreate; separate installation/runtime Secret boundaries; deny-default networking; signed OAuth headers on loopback HTTP and TLS requirement for production. No extra services for later milestones. Core/plugin upgrades on persisted files require an explicit future migration/recovery procedure.
