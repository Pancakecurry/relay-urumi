# M2 — Store MCP and independent utility upstreams

Date: October 10, 2026. Local Kubernetes acceptance passed; Git/export reproduction results are recorded below when checkpointed. This is M2 only. No production gateway, team identity, dashboard, autonomous multi-server model prompt, VPS or bonus completion is claimed.

**Implemented:**

- `apps/woocommerce-mcp/src/{server,rest}.ts`: handwritten five required REST v3 tools plus `info`. Strict bounded schemas, published/visible defaults, unique SKU, explicit pages, supported order statuses, exact decimal strings and UTC half-open order ranges. Fixed configured store origin; no caller-supplied URL/credential.
- `apps/calendar-mcp/src/server.ts`: independent `now`, `day_range`, `info`; actual clock, IANA timezone, DST and skipped dates. `apps/totals-mcp/src/server.ts`: independent `sum_amounts`, `sum_orders`, `info`; BigInt exact arithmetic, mixed-currency/duplicate rejection.
- `packages/contracts/src/domain.ts`, `packages/mcp-runtime/src/server.ts`: shared strict contracts, hardened v2 Streamable HTTP, distinct bearer auth, Host/Origin checks, structured results and sanitized business/transport errors. No retries of ambiguous writes.
- `packages/mcp-client/src/{routes,m2-acceptance,m2-fault}.ts`: bounded immutable-ID alias table and actual SDK acceptance/fault clients. Route table exercise is not the M3 public gateway.
- `charts/hosted-mcp/`, `infra/local/mcp-*.yaml`, `infra/prod/mcp-values.example.yaml`: three separate private deployments, probes/limits, non-root/read-only root, no service-account token, separate Secret mounts, restricted ingress/egress. The Woo adapter alone mounts `store-adapter`.
- `scripts/mcp-*.mjs`, `scripts/mcp-deploy.sh`: owned/idempotent Secret handling, reproducible image/Helm deployment, live acceptance, network checks, Inspector diagnostics, controlled failure/recovery and inventory. M0 Docker build inputs support the expanded frozen workspace. Store checkout tests now locate the stable SKU and can write regression evidence separately, preserving historical M1 captures.
- ADR 0007, versions/architecture/runbook/demo/requirements/worklog are maintained. Current official brief text was fetched again and matches the October 9 snapshot after whitespace normalization: [source-validation.json](m2/source-validation.json).

The M1 existing-order capture retains that test's historical `afterPodReplacement` label; M2 did not perform another WordPress/database pod replacement. Original persistence acceptance remains in M1. Inspector's loopback-only administrator port-forward is a diagnostic exception, not a public MCP route. **Failed or blocked:**

Observed and repaired: strict compile issues; test-only order creation denied by the deliberately restricted service role; a Node fetch Host probe that did not send the forged header; HPOS GMT Z-suffix boundary behavior; and a fault test that wrongly expected a timeout from K3s's immediate network rejection. See [repairs.md](m2/repairs.md) and retained sanitized failure capture. No mandatory M2 failure remains after final checks. Cluster import cleanup emitted one transient tools-container race warning; subsequent imports were sequential, with actual image/runtime verification.

Production authenticated gateway, autonomous external/chat prompts, TLS/mTLS, VPS and multi-store provisioning remain later gates. HTTP within this local cluster is **unencrypted**. TLS REST code is not a claim of deployed HTTPS interoperability. Standard seven order statuses and six explicitly supported currency scales are current limits; custom plugin statuses/other currencies require deliberate extension. Pagination has no snapshot-isolation guarantee under concurrent store writes. No SMTP is configured; synthetic order email failures remain the M1 known limitation.

**Architecture decisions:**

ADR [0007](../decisions/0007-private-store-upstreams.md): SDK-owned stateless transport; three process/deployment boundaries; server-side file credentials; canonical signed REST origin with private service routing; GMT encoding verified on pinned HPOS; BigInt/Temporal; explicit bounded routes/results/errors. No SDK-generation change or production authorization bypass. Pure route helper and privileged fixture prepare M3 without pretending it is implemented.
