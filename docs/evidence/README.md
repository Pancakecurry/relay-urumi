# Execution evidence

These files contain actual local command outputs or structured assertions produced by the M0 scripts. Text logs are normalized only by removing ANSI color escapes and trailing whitespace/extra final blank lines; outcomes, errors and warnings are retained. Snapshot files include their collection time. They are evidence of that run, not continuously updated monitoring.

No Secret values, key-bearing configurations, kubeconfigs, personal hiring correspondence or cloud-account metadata belong here. The staged-file credential scan checks known private values and common key patterns; it is a bounded scan, not proof against every possible sensitive-data encoding.

`M0_REPORT.md` distinguishes executed acceptance from pending product/external dependencies. Future-only requirement evidence must be collected at the responsible milestone.
