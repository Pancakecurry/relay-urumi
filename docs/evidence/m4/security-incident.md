# M4 local cluster inventory disclosure

The first clean-install collector printed raw k3d JSON. That JSON included the owned `relay-m0` node-join token in container labels/environment. The value appeared in local evidence and one private task tool output. It was not intentionally published or committed. This disclosure must not be described as “no credentials ever exposed.” No Gemini, WooCommerce, personal API key, or user password was involved in this incident.

The collector was stopped before a second cluster was created. The local evidence value was replaced with `[REDACTED]`; its known value was retained only in an ignored 0600 incident file for credential scans. The corrected collector reads raw inventory privately and emits only cluster names and server/agent counts. Kubeconfig and rotation command output also stay private.

The working cluster must retain its persistent data. Rotation is therefore gated by a disposable single-server restart proof using the exact selected K3s version. The rotation procedure saves a quiesced private server-data backup, configures persistent token-file startup, performs official token rotation, and requires an actual restart, old-token HTTP 401, new-token HTTP 200, and unchanged PVC identities. See the runbook and the eventual `clean-token-rotation.json` / `token-rotation.json` outputs for executed results. Both rotation outputs now pass: the old credential returns HTTP 401, the new credential returns HTTP 200, the API/node recover after an actual Docker restart, and all PVC identities remain unchanged. The working cluster repair is complete; application regressions are recorded separately.

The private tool transcript cannot be edited by this implementation. Rotation invalidates the disclosed credential; redaction alone is not the security fix. K3d's stale metadata retains the now-invalid old token after rotation, so future node additions need the current private token explicitly. Preserve old tokens with pre-rotation snapshots as required by K3s.

The disposable test first caught a helper that dropped stdin, leaving the token-file configuration empty. That cluster failed to restart and was removed; the working cluster was untouched. Fixed stdin forwarding, explicit read-back, bounded health requests, and verified actual Docker loopback bindings before applying the proven procedure. Sanitized failure evidence is preserved.
